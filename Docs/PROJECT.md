# Project Tango - 프로젝트 헌장 (Project Charter)

## 1. 프로젝트 개요 및 포지셔닝
- **주제:** UE5 데디케이티드 서버 기반 3인칭 전술 익스트랙션 슈터 (소규모 아레나 버전)
- **타겟 포지션:** 언리얼 클라이언트 프로그래머 (유니티 클라이언트 4년 경력자의 언리얼 멀티플레이 전환 포트폴리오)
- **핵심 목표:** 단순한 콘텐츠 나열이 아닌, **서버 권한(Server Authority) 기반 아키텍처에 대한 이해**와 **네트워크 지연 상황에서의 클라이언트 체감 품질(예측, 보간, UI 즉시 반영 및 롤백)**을 높은 완성도의 C++ 코드로 증명한다.

---

## 2. 최종 납품물 (Deliverables)
1. **기술 시연 영상 (3분 이내):** 아래 3대 핵심 장면을 중심으로 구성된 쇼케이스 영상.
   - 컷 1: 데디케이티드 서버 기반 코어 매치 루프 (스폰 → 파밍 → 교전 → 탈출 → 결과)
   - 컷 2: 지연 환경(200ms)에서의 사격 리와인드(Server-Side Rewind) On/Off 비교 및 과거 히트박스 시각화
   - 컷 3: 지연 환경(200ms)에서의 동시 루팅 경합 및 낙관적 UI 즉시 반영/거절 롤백 시연
2. **기술 설계 및 트러블슈팅 문서:** 마지막에 몰아서 쓰지 않고 매 Step 종료 시점에 누적 작성하는 아키텍처 설계 의도, 네트워크 동기화/검증 구조, 유니티 대비 언리얼 프레임워크 활용 기록.
3. **GitHub 리포지토리:** C++ 중심의 클린 아키텍처 코드와 체계적인 이슈/마일스톤/PR 히스토리.
4. **데디케이티드 서버 + 클라이언트 실행 패키지:** 원클릭(배치 파일)으로 로컬에서 데디케이티드 서버와 다중 클라이언트를 구동해 즉시 검증 가능한 빌드.

## 3. 핵심 기술 역량 (Core Pillars)

### 축 1. 사격 판정과 지연 보상 (Shooting & Lag Compensation)
- **서버:** 서버 권한 사격 판정, 과거 위치 히스토리 기반 리와인드(Server-Side Rewind) 판정.
- **클라이언트:** 발사 즉시 재생되는 로컬 예측 연출(총구 화염, 탄흔), 타 플레이어 이동 보간, 명중 피드백.

### 축 2. 인벤토리 복제와 루팅 권한 (Inventory Replication & Looting Authority)
- **서버:** 서버 권한 루팅 검증, 변경된 부분만 전송하는 델타 복제(Delta Serialization).
- **클라이언트:** 아이템 획득 시 지연 없이 UI에 즉시 반영(Optimistic UI)하고, 동시 루팅 경합 등으로 서버가 거절(Reject)할 경우 원래 상태로 복구하는 롤백(Rollback) 처리.

### 기본기 (Foundations)
- C++ 중심의 역할 분리 아키텍처 (`GameMode`, `GameState`, `PlayerState`, `Character`, `ASC`)
- GAS(Gameplay Ability System) 기초: 체력, 데미지, 전술 스킬 (최소 1종 필수, 목표 2종)
- 데디케이티드 서버 패키징

## 4. 스코프, 우선순위(Cut-line) 및 매치 규칙

### 기능 우선순위 (MoSCoW 컷 라인) 및 착수 순서 원칙
- **Must-First 착수 원칙:** 모든 `Must` 핵심 기능은 1~6주 차(Step 1~3)에 우선 배치하여 먼저 완료한다. 조건부 항목(`Should`, `Could`)은 모든 개별 `Must` 기능이 완성된 뒤인 **Step 4(7주 차)**에만 `Must(통합) → Should → Could` 순서로 착수한다.
- **Must (절대 타협 불가 - Step 1~4 완료 기준의 필수 전제):**
  - 데디케이티드 서버 빌드/접속 파이프라인
  - GAS 기반 체력/데미지, 기본 사격 어빌리티 및 **전술 스킬 1종** (Step 2에서 사격과 함께 필수 구현)
  - 사격 서버 리와인드 판정, 클라이언트 예측 연출, 리와인드 히트박스 디버그 시각화
  - 인벤토리 델타 복제, 월드 아이템 루팅, 낙관적 UI 즉시 반영 및 서버 거절 시 롤백
  - 최소 매치 루프 (진입 → 파밍 → 교전 → 개별 탈출 점령 → 결과 화면) 및 전체 루프 통합
- **Should (완성도 강화 요소 - Step 4 배치):**
  - 사망 시 보유 아이템을 드랍하는 데스박스(Death Box) 생성 및 컨테이너 루팅
  - 탈출 구역 점령 중 다른 적 침입 시 '경합(Contested)' 일시정지 기믹
- **Could (일정 부족 시 최우선 제거 대상 - Step 4 배치):**
  - **2번째 GAS 전술 스킬** (구현 시 총 2종, 컷할 경우 Step 2에서 구현한 Must 1종만 유지)
  - 사망 후 대기 시간을 거쳐 외곽에 기본 무장으로 재스폰(Respawn)하는 기능 (컷할 경우 사망 즉시 영구 사망 처리)
  - 결과 화면 내 상세 교전 통계 (가한 총 데미지, 명중률 등 부가 지표)
- **Won't (Out of Scope - 처음부터 배제):**
  - 아웃게임 로비, 매치메이킹, 상점/창고(Stash), 로그인 시스템
  - AI 몬스터(PvE) 및 비헤이비어 트리
  - 다수의 무기/파츠 개조 및 대량의 아이템 테이블 양산
  - 과도한 아트/레벨 디자인 및 그래픽 폴리싱

### 컷 결정 트리거 및 기능 동결 (Checkpoints & Feature Freeze)
8주 차(최종 패키징 및 영상 제작 주간)가 개발 지연으로 침범당하는 것을 막기 위해 다음 시점에 강제 스코프 조정을 발동한다.
1. **Checkpoint 1 (4주 차 종료 시점):** Step 2의 `Must` 완료 기준을 충족하지 못했을 경우, **즉시 모든 `Could` 항목(2번째 전술 스킬, 리스폰, 부가 통계)을 프로젝트 범위에서 영구 제외(Cut)**하고 Step 4 시간을 지연 만회에 할당한다.
2. **Checkpoint 2 (6주 차 종료 시점):** Step 3의 `Must` 완료 기준을 충족하지 못했을 경우, **즉시 남아있는 `Should` 항목(데스박스 드랍, 탈출 경합 일시정지)까지 모두 제외(Cut)**하고 7주 차에는 오직 필수 기능 마무리와 매치 루프 통합만 수행한다.
3. **Checkpoint 3 / Feature Freeze (7주 차 종료 시점):** 7주 차 종료 시점에 **신규 기능 개발을 전면 동결(Feature Freeze)**한다. 미완성된 `Should`/`Could` 항목이 남아있더라도 즉시 폐기(Revert)하며, **8주 차에는 오직 안정화(버그 수정)와 최종 납품물(패키징, 시연 영상, README) 제작만 수행**한다.

### 매치 흐름 및 명확한 판정 규칙 (5분 아레나 루프)
1. **진입 (Entry):** 2~4명의 플레이어가 접속 후 짧은 대기/카운트다운을 거쳐 기본 무장(기본 총기 및 탄약) 상태로 맵 외곽에 동시 스폰한다.
2. **파밍 (Looting):** 맵 중앙 위험 구역의 고가치 전리품 및 탄약/회복 아이템을 파밍한다 (동시 루팅 경합 및 UI 롤백 시연 무대).
3. **교전 및 사망 판정 (Combat & Death):**
   - 사격 및 GAS 스킬을 활용해 교전하며, 체력이 0이 된 플레이어는 사망 판정을 받는다 (`Should`: 사망 위치에 보유 아이템이 담긴 데스박스 생성).
   - **사망 처리 규칙:** 기본(`Must`) 규칙은 사망 즉시 해당 플레이어를 '탈출 실패(KIA)' 결과 화면으로 전환하는 영구 사망 방식이다. 단, Step 4에서 리스폰(`Could`)을 추가 구현할 경우 사망 후 일정 시간(예: 5초) 뒤 외곽에서 기본 무장으로 재스폰한다.
4. **탈출 판정 (Extraction - 개별 탈출 규칙):**
   - 활성화된 탈출 구역 진입 시 개인 점령 타이머가 작동한다 (`Should`: 구역 내 적 침입 시 경합 상태가 되어 타이머 일시 정지).
   - **개별 탈출 규칙:** 점령 타이머를 끝까지 채운 플레이어는 매치 전체를 끝내지 않고 **해당 플레이어만 즉시 맵에서 이탈하여 본인의 '탈출 성공(Extracted)' 결과 화면으로 전환**된다. 남은 플레이어들은 제한 시간이 끝날 때까지 매치를 계속 진행한다.
5. **매치 종료 및 결과 판정 (Match End & Result):**
   - **매치 종료 조건:** 5분 제한 시간이 모두 소진되거나, 맵에 남아있는 활성 플레이어가 0명(전원 탈출 완료 또는 전원 영구 사망)이 되면 서버 매치가 종료된다.
   - **결과 판정 규칙:** 매치 종료 시점까지 탈출 구역을 통해 빠져나가지 못한 모든 플레이어는 리스폰 여부와 무관하게 전원 **'탈출 실패(MIA / Time Over)'**로 최종 판정하며, 결과 화면에 성공/실패 여부와 최종 보유 전리품 목록을 표시한다.

## 5. 리스크 관리 원칙 (Risk Management Principles)
1. **1인 멀티플레이 테스트 및 시연 보장:** 혼자서도 지연 보상 사격과 동시 루팅 경합을 테스트하고 촬영할 수 있도록 보조 장치(이동 더미, 경합 시뮬레이션 등)를 함께 구축한다.
2. **네트워크 로직의 시각화:** 내부에서 동작하는 리와인드 판정과 인벤토리 예측/롤백 상태가 화면에서 직관적으로 보이도록 디버그 시각화 기능을 함께 제공한다.
3. **데디케이티드 서버 빌드 조기 검증:** 패키징 이슈를 막바지에 겪지 않도록 Step 1에서 데디케이티드 서버 빌드 및 접속 파이프라인을 먼저 검증한다.
4. **공개 리포지토리 에셋 라이선스 및 용량 통제 (납품 리스크 방지):**
   - Public GitHub 리포지토리에 재배포가 금지된 외부 유료/무료 서드파티 에셋(Fab/마켓플레이스 등)을 커밋하지 않는다.
   - 원칙적으로 **언리얼 엔진 기본 템플릿 에셋(Third Person / Lyra 마네킹 및 기본 애니메이션)과 기본 블록아웃 지오메트리만 사용**한다.
   - **라이선스 근거:** [Unreal Engine EULA (Section 1.B & Examples/Starter Content 배포 조항)](https://www.unrealengine.com/ko/eula/unreal) 및 [Fab EULA](https://www.fab.com/eula)에 따라, 에픽게임즈가 제공하는 공식 샘플 콘텐츠(Lyra Starter Game, 템플릿 에셋 등)는 언리얼 엔진 기반 프로젝트 내에서 사용되는 한 다른 언리얼 엔진 라이선스 사용자에게 소스/에셋 형태로 공개 배포(GitHub 등)하거나 실행 파일로 패키징해 배포하는 것이 허용된다(타 엔진 반출 및 에셋 단독 판매만 금지). 이 근거와 에셋 출처 고지를 최종 `README.md`에 명시한다.

## 6. 마일스톤 일정 및 완료 기준 (Timeline & Definition of Done)
- **가용 리소스:** 평일 하루 2시간(주 10시간) + 주말 하루 4~6시간(주 8~12시간) = **주간 약 20시간**
- **목표 기간:** **총 8주 (약 160시간 - 필수 기능 개발 6주 + 통합 및 조건부 확장 1주 + 최종 패키징/영상 1주)**
- **완료 판정 원칙:** Step 1~3에는 오직 `Must` 항목만 배치하여 6주 차까지 포트폴리오의 모든 필수 기능을 완료한다. 모든 Step의 완료 기준(DoD)은 **`Must` 항목만으로 관찰 및 측정 가능하게 정의**한다.

| :--- | :---: | :--- | :--- | :--- |

| **Step 2** | 3~4주 차 (40h) | 전투 기초 & 핵심 역량 1 (사격/리와인드/스킬 1종) | - **[Must]** GAS 체력/데미지, 기본 사격 및 예측 연출, **GAS 전술 스킬 1종**, 서버 리와인드 판정, 이동 더미 및 히트박스 시각화 | 200ms 지연 환경에서 전술 스킬 1종이 정상 발동(쿨타임/이펙트 동기화)되고, 일정 속도로 이동하는 더미를 사격할 때 리와인드 On/Off에 따른 명중 판정(체력 차감 여부) 차이와 서버 과거 히트박스 위치가 화면 디버그 드로잉으로 표시된다. (+Step 2 기술 문서 초안 커밋 완료) |
| **Step 3** | 5~6주 차 (40h) | 핵심 역량 2 (인벤토리/루팅 롤백) | - **[Must]** 델타 복제 인벤토리, 월드 아이템 루팅, 낙관적 UI 즉시 반영 및 경합 거절 시 롤백 | 200ms 지연 환경에서 월드 아이템 루팅 입력 즉시 클라이언트 UI 슬롯에 아이템이 표시(`Pending`)되며, 동시 루팅 경합 패배 시 서버 거절(`Reject`) 응답 수신 직후 해당 슬롯이 원래 상태(빈 슬롯)로 복구되고 `Pending → Rejected` 상태 전환 로그가 화면 디버그 UI에 표시된다. (+Step 3 기술 문서 초안 커밋 완료) |
| **Step 4** | 7주 차 (20h) | 전체 매치 루프 통합 & 조건부 확장 | - **[Must]** 전체 매치 루프(스폰-파밍-교전/스킬-탈출-결과) 통합 및 안정화<br>- **[Should]** *(Must 완료 후 착수)* 사망 시 데스박스 드랍, 탈출 구역 경합 일시정지<br>- **[Could]** *(Should 완료 후 착수)* 2번째 GAS 전술 스킬, 사망 후 리스폰, 상세 교전 통계 | **[7주 차 말 Feature Freeze]** GAS 전술 스킬(최소 1종), 월드 루팅, 사격 교전, 개별 탈출이 통합된 5분 매치 1판 진행 중 서버/클라이언트 크래시 및 Ensure 실패가 0건이며, 매치 종료 시점의 클라이언트 UI 표시 값(체력, 보유 아이템 수, 탈출 결과)이 서버 권위 값과 100% 일치한다. (+Step 4 기술 문서 초안 커밋 완료) |
| **Step 5** | 8주 차 (20h) | 최종 안정화, 패키징 및 산출물 완성 | - **[Must]** 잔여 버그 수정, 원클릭 실행 배치 파일 패키징, 3분 시연 영상 촬영, README 기술 문서 및 에셋 라이선스 고지 최종 정리 | 원클릭 실행 배치 파일(`Server + 2 Clients`) 실행 시 추가 설정 없이 매치 진입이 가능하며, 3분 이내의 시연 영상 링크와 최종 기술 문서가 GitHub 리포지토리에 게시 완료된다. |

## 7. GitHub 리포지토리 및 이슈 운영 규칙 (Workflow Rules)
면접관이 코드 변경 이력과 엔지니어링 프로세스를 명확히 파악할 수 있도록 아래 규칙을 준수하되, 1인 개발의 작업 오버헤드를 최소화한다.

1. **마일스톤 및 이슈 매핑 (Milestone & Issue):**
   - 위 `Step 1` ~ `Step 5`를 각각 GitHub **Milestone**으로 등록한다.
   - 각 작업은 1회 작업 세션(**평일 2시간 또는 주말 4~6시간**) 내에 완료할 수 있는 크기의 **GitHub Issue**로 생성하며, 본문에는 `[작업 요약 / 체크리스트 / 완료 확인 기준]`을 간결하게 기재한다.
   - 각 Step 내에서도 `Must` 이슈를 모두 닫은(Close) 뒤에야 `Should` → `Could` 이슈를 생성/착수한다.
2. **브랜치 및 Pull Request 전략 (Branch & PR):**
   - 기능 구현 이슈는 별도 브랜치(`feat/<이슈번호>-<요약>`, `fix/<이슈번호>-<요약>`)에서 작업한 뒤 **Pull Request(PR)**를 통해 `main` 브랜치에 병합(Merge)하여 기능 단위의 코드 리뷰 히스토리를 남긴다.
   - 단, 단순 문서 오탈자 수정이나 사소한 설정 변경(`docs:`, `chore:`)은 작업 속도 유지를 위해 `main` 브랜치 직접 커밋을 허용한다.
3. **커밋 메시지 컨벤션 (Conventional Commits):**
   - `feat:` (신규 기능), `fix:` (버그 수정), `refactor:` (리팩토링), `docs:` (문서 작업), `chore:` (빌드/패키징/설정) 접두사를 사용하고 관련 이슈 번호(`#N`)를 명시한다.
   - 예: `feat: implement lag compensation hitbox ring buffer (#12)`
