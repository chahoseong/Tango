# Project Tango

## 1. 프로젝트 정의

**Project Tango**는 언리얼 엔진 5(Unreal Engine 5) 데디케이티드 서버(Dedicated Server) 기반의 3인칭 전술 익스트랙션 슈터(Tactical Extraction Shooter) 프로젝트입니다. 2~4명의 플레이어가 하나의 아레나 맵에서 5분 동안 무기와 전리품을 파밍하고, 교전을 벌인 뒤, 탈출 구역을 점령해 빠져나오면 끝납니다.

이 프로젝트는 **언리얼 엔진의 멀티플레이 구조**와 **네트워크 동기화**를 구현합니다. 서버가 판정 권한(Server Authority)을 가진 환경에서, 네트워크 지연이 발생해도 클라이언트의 조작감과 UI 반응성이 떨어지지 않도록 처리합니다.

---

## 2. 최종 산출물

1. **기술 시연 영상 (3분 이내):** 핵심 기능이 동작하는 모습을 담은 세 가지 장면으로 구성합니다.
   - **코어 매치 루프:** 진입부터 파밍, 교전, 개별 탈출, 결과 화면까지 한 판의 진행 과정을 보여줍니다.
   - **지연 보상과 되감기 판정:** 고지연(200ms) 환경에서 되감기 판정(Server-Side Rewind)을 켰을 때와 껐을 때의 명중 결과 차이를 과거 판정 위치 시각화와 함께 비교합니다.
   - **루팅 경합과 UI 롤백:** 고지연(200ms) 환경에서 아이템을 줍는 즉시 UI에 선반영(Client Prediction)되는 모습과, 동시 루팅 경합에서 패배했을 때 서버 거절 응답에 따라 원래 상태로 롤백(Rollback)되는 과정을 보여줍니다.
2. **기술 설계 및 트러블슈팅 문서:** 아키텍처 설계 이유, 네트워크 동기화와 검증 구조, 유니티와 다른 언리얼 프레임워크 활용 방식을 기록합니다. 마지막에 몰아서 쓰지 않고 각 단계가 끝날 때마다 누적해서 작성합니다.
3. **GitHub 리포지토리:** C++ 중심의 코드와 마일스톤, 이슈, 풀 리퀘스트(Pull Request) 단위로 정리된 개발 이력을 남깁니다.
4. **원클릭 실행 패키지:** 실행 스크립트 한 번으로 로컬 환경에서 데디케이티드 서버와 다중 클라이언트를 동시에 띄워 즉시 테스트할 수 있는 빌드 묶음을 만듭니다.

## 3. 기술 목표

### 1. 사격 판정과 지연 보상 (Lag Compensation)
- **서버:** 사격 판정의 최종 권한을 가지며, 클라이언트가 발사한 시점의 과거 위치로 대상을 되감아(Rewind) 명중 여부를 판정합니다.
- **클라이언트:** 사격 입력 즉시 총구 화염과 탄흔 등 발사 연출을 로컬에서 먼저 재생하고, 다른 플레이어의 이동을 보간(Interpolation)하며 명중 피드백을 표시합니다.

### 2. 인벤토리 복제와 루팅 권한 (Inventory Replication & Authority)
- **서버:** 아이템 획득과 이동 권한을 검증하며, 전체 인벤토리가 아닌 변경된 부분만 클라이언트로 복제(Delta Replication)합니다.
- **클라이언트:** 아이템을 집는 즉시 UI에 선반영하여 입력 지연을 없애고, 동시 루팅 경합 등으로 서버가 요청을 거절하면 원래 상태로 롤백합니다.

### 3. 멀티플레이 기본 구조, GAS, 서버 패키징
- **C++ 중심의 역할 분리:** 서버 규칙 판정, 매치 상태 공유, 플레이어 영속 데이터, 캐릭터 아바타 표현의 책임을 언리얼 멀티플레이 프레임워크의 역할에 맞춰 C++로 분리합니다.
- **GAS(Gameplay Ability System) 기초:** 체력과 데미지 처리, 기본 사격, 전술 스킬을 GAS 기반으로 구현합니다.
- **매치 흐름과 데디케이티드 서버 패키징:** 진입부터 결과까지의 매치 상태 전환과 독립 실행형 서버 패키징을 완성합니다.

## 4. 게임 규칙

우리가 구현한 핵심 기술을 가장 잘 보여주고 반복 테스트를 쉽게 할 수 있도록 게임의 규칙을 다음과 같이 정합니다.

1. **진입:** 2~4명의 플레이어가 접속하면 짧은 카운트다운을 거친 뒤, 기본 무장(기본 총기와 탄약)을 갖춘 상태로 맵 외곽에 동시에 스폰됩니다.
2. **파밍:** 맵 중앙 위험 구역에 배치된 고가치 전리품과 탄약, 회복 아이템을 파밍합니다. 플레이어들이 이 구역으로 모이면서 동시 루팅 경합과 교전이 발생합니다.
3. **교전 및 사망:** 사격과 전술 스킬을 사용해 교전을 벌이며, 체력이 0이 된 플레이어는 사망 판정을 받습니다.
   - **기본 규칙 (`Must`):** 사망한 플레이어는 즉시 매치에서 이탈하며 **'탈출 실패(KIA)'** 결과 화면으로 전환됩니다.
   - **데스박스 (`Should`):** 사망 위치에 보유 아이템이 담긴 데스박스(Death Box)를 떨어뜨립니다.
   - **리스폰 (`Could`):** 사망 시 즉시 이탈하지 않고, 일정 대기 시간 후 맵 외곽에서 기본 무장으로 다시 스폰됩니다.
4. **개별 탈출:** 활성화된 탈출 구역에 들어가 일정 시간 동안 점령을 유지하면 탈출합니다.
   - **개별 탈출 처리:** 점령을 마친 플레이어는 매치 전체를 끝내지 않고 본인만 즉시 맵에서 빠져나가 **'탈출 성공'** 결과 화면을 봅니다. 남은 플레이어는 제한 시간이 끝날 때까지 매치를 계속 진행합니다.
   - **경합 처리 (조건부):** 점령 도중 다른 적이 구역 안으로 들어오면 **'경합 중'** 상태가 되어 점령 진행이 일시 정지됩니다.
5. **매치 종료 및 결과:** 5분 제한 시간이 모두 지나거나 맵에 남은 플레이어가 0명(전원 탈출 또는 전원 사망)이 되면 매치가 종료됩니다. 종료 시점까지 탈출하지 못한 플레이어는 모두 **'탈출 실패(시간 초과)'**로 판정하며, 결과 화면에 성공 여부와 최종 획득 전리품을 표시합니다.

## 5. 개발 범위와 우선순위

제한된 시간 안에 핵심 기술의 완성도를 지키기 위해 모든 기능을 네 단계의 우선순위(MoSCoW)로 나눕니다. 항상 **필수(Must) 항목을 먼저 완성한 뒤에 조건부 항목(Should → Could)을 진행**합니다.

| 구분 | 기준 | 대상 기능 |
| :--- | :--- | :--- |
| **Must** | **필수**<br>(모든 단계의 완료 판정 기준) | • 데디케이티드 서버 빌드와 다중 클라이언트 접속 환경<br>• GAS 기반 체력/데미지, 기본 사격, **전술 스킬 1종**<br>• 서버 되감기 사격 판정, 클라이언트 예측 연출, 과거 판정 위치 시각화<br>• 인벤토리 변경분 복제, 월드 아이템 루팅, UI 선반영 및 거절 시 롤백<br>• 최소 매치 루프(진입 → 파밍 → 교전/영구 사망 → 개별 탈출 → 결과)와 전체 통합 |
| **Should** | **권장**<br>(필수 기능 완료 후 추가) | • 사망 시 보유 아이템을 떨어뜨리는 데스박스 생성 및 상자 루팅<br>• 탈출 구역 점령 중 적 진입 시 진행이 멈추는 경합 일시정지 규칙 |
| **Could** | **선택**<br>(일정 지연 시 가장 먼저 제외) | • **2번째 GAS 전술 스킬** (추가 구현 시 총 2종, 제외 시 필수 1종만 유지)<br>• 사망 후 대기 시간을 거쳐 외곽에 기본 무장으로 재스폰하는 기능<br>• 결과 화면의 상세 교전 통계(가한 데미지, 킬 수 등 부가 지표) |
| **Won't** | **제외**<br>(처음부터 만들지 않음) | • 아웃게임 로비, 매치메이킹, 상점과 창고, 로그인 시스템<br>• 인공지능 몬스터(PvE)<br>• 총기 파츠 개조 및 다수의 무기·아이템 양산<br>• 과도한 아트 리소스 제작, 복잡한 레벨 디자인, 그래픽 폴리싱 |

### 범위 축소 기준점 (Checkpoints)
마지막 8주 차의 패키징과 영상 제작 시간을 보호하기 위해 세 번의 기준점을 두고 범위를 조정합니다.

1. **4주 차 종료 시점 (1차 기준점):** Step 2의 필수 완료 기준을 통과하지 못하면, **Could 항목**을 모두 제외하고 핵심 기능 개발에 집중합니다.
2. **6주 차 종료 시점 (2차 기준점):** Step 3의 필수 완료 기준을 통과하지 못하면, **Should 항목**까지 모두 제외하고 7주 차에는 필수 기능 마무리와 매치 통합만 진행합니다.
3. **7주 차 종료 시점 (기능 동결 / Feature Freeze):** 7주 차가 끝나면 새로운 기능 추가를 전면 중단합니다. 미완성된 조건부 기능은 제외하고, 8주 차에는 버그 수정과 최종 산출물 제작만 진행합니다.

## 6. 일정과 완료 기준

평일 5일 동안 하루 2시간(주 10시간), 주말 이틀 동안 하루 4~6시간(주 약 10시간)을 합쳐 **주간 약 20시간, 총 8주(160시간)** 동안 진행합니다. 1~6주 차(Step 1~3)에는 필수 항목(`Must`)만 배치하여 핵심 기능을 먼저 끝내고, 모든 단계의 완료 여부는 필수 기준으로만 판정합니다.

### 전체 일정 요약

| 단계 | 기간 (시간) | 목표 | 핵심 산출물 |
| :--- | :---: | :--- | :--- |
| **Step 1** | 1~2주 차 (40h) | 기반 환경과 최소 매치 흐름 | 데디케이티드 서버 빌드/접속, 3인칭 기본 이동, 진입-타이머-개별 탈출-결과 루프 |
| **Step 2** | 3~4주 차 (40h) | 전투 기초와 사격 지연 보상 | GAS 체력/데미지, 사격 및 예측 연출, 전술 스킬 1종, 되감기 판정 및 시각화, Step 2 문서 |
| **Step 3** | 5~6주 차 (40h) | 인벤토리 복제와 루팅 롤백 | 인벤토리 변경분 복제, 월드 루팅, UI 선반영 및 경합 거절 롤백, Step 3 문서 |
| **Step 4** | 7주 차 (20h) | 전체 루프 통합과 조건부 확장 | 5분 매치 전체 통합 검증(`Must`), 데스박스와 탈출 경합(`Should`), 2번째 스킬과 리스폰(`Could`), Step 4 문서 |
| **Step 5** | 8주 차 (20h) | 안정화, 패키징, 최종 산출물 | 원클릭 실행 패키지, 3분 시연 영상, 최종 `README.md` 및 기술 문서 |

### 단계별 완료 기준 (Definition of Done)

- **Step 1 완료 기준:** 로컬 데디케이티드 서버에 클라이언트 2개가 접속해 동시에 스폰됩니다. 한 클라이언트가 탈출 구역 점령을 마치면 해당 클라이언트만 즉시 '탈출 성공' 화면으로 전환되고, 제한 시간이 끝나면 남은 클라이언트에 '탈출 실패' 화면이 정상 출력됩니다.
- **Step 2 완료 기준:** 200ms 지연 환경에서 전술 스킬 1종의 쿨타임과 연출이 정상 동기화됩니다. 일정한 속도로 움직이는 더미를 사격할 때, 되감기 판정 활성화(On/Off) 여부에 따른 명중 결과 차이와 서버가 되감은 과거 판정 위치가 화면에 시각적으로 표시됩니다. Step 2 설계 문서 초안을 작성합니다.
- **Step 3 완료 기준:** 200ms 지연 환경에서 월드 아이템을 줍는 즉시 클라이언트 UI에 아이템이 선반영됩니다. 동시 루팅 경합에서 패배해 서버 거절 응답을 받으면 해당 슬롯이 원래 상태로 복구되고, 선반영부터 롤백까지의 상태 전환이 디버그 화면에 표시됩니다. Step 3 설계 문서 초안을 작성합니다.
- **Step 4 완료 기준:** 전술 스킬(최소 1종), 월드 루팅, 사격 교전, 개별 탈출이 하나로 이어진 5분 매치 한 판을 런타임 오류 없이 완주합니다. 체력이 0이 된 클라이언트는 즉시 '탈출 실패(KIA)' 화면으로 전환되며, 맵에 남은 플레이어가 0명이 되면 제한 시간과 관계없이 매치가 종료됩니다. 매치 종료 시점에 클라이언트 화면에 표시된 체력, 보유 아이템 수, 탈출 결과가 서버의 실제 값과 일치합니다. Step 4 설계 문서 초안을 작성합니다.
- **Step 5 완료 기준:** 원클릭 실행 스크립트로 서버와 클라이언트 2개를 바로 띄워 매치를 플레이할 수 있으며, 3분 시연 영상과 최종 정리된 기술 문서를 리포지토리에 게시합니다.

## 7. 실행 원칙과 워크플로우

### 리스크 관리 원칙
1. **1인 테스트 보조 장치 구축:** 혼자서도 지연 보상 사격과 동시 루팅 경합을 테스트하고 촬영할 수 있도록, 왕복 이동 더미와 루팅 경합 시뮬레이션 기능을 함께 만듭니다.
2. **네트워크 동작의 시각화:** 눈에 보이지 않는 서버 되감기 판정과 인벤토리 선반영·롤백 상태를 화면에서 바로 확인할 수 있도록 디버그 표시 기능을 함께 구현합니다.
3. **서버 패키징 조기 검증:** 마지막 주에 패키징 문제로 일정이 밀리지 않도록, Step 1에서 데디케이티드 서버 빌드와 클라이언트 접속을 먼저 확인합니다.
4. **에셋 라이선스와 용량 통제:** 공개 리포지토리에 재배포가 금지된 외부 서드파티 에셋을 올리지 않습니다. 시각 리소스는 언리얼 엔진 기본 템플릿(Third Person / Lyra 샘플)과 기본 블록아웃 도형만 사용합니다. 에픽게임즈 공식 샘플은 언리얼 엔진 프로젝트 내 사용 시 공개 배포가 허용되며([Unreal Engine EULA](https://www.unrealengine.com/ko/eula/unreal), [Fab EULA](https://www.fab.com/eula)), 최종 `README.md`에 출처와 라이선스를 명시합니다.

### GitHub 운영 규칙
1. **마일스톤과 이슈:** `Step 1` ~ `Step 5`를 각각 GitHub Milestone으로 등록합니다. 개별 작업은 한 번의 작업 시간(평일 2시간 또는 주말 4~6시간) 안에 끝낼 수 있는 크기의 Issue로 만들고, `[작업 요약 / 체크리스트 / 완료 확인 기준]`만 간결하게 적습니다.
2. **브랜치와 풀 리퀘스트:** 기능 구현과 버그 수정은 별도 브랜치(`feat/<이슈번호>-<요약>`, `fix/<이슈번호>-<요약>`)에서 작업한 뒤 Pull Request(PR)를 통해 `main`에 병합합니다. 단순 문서 수정이나 설정 변경(`docs:`, `chore:`)은 `main` 직접 커밋을 허용합니다.
3. **커밋 메시지:** `feat:`, `fix:`, `refactor:`, `docs:`, `chore:` 접두사와 관련 이슈 번호(`#N`)를 함께 적습니다.
